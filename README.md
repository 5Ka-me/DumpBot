# Dump Bot

Личный Telegram-бот-«свалка». Кидаете в него всё подряд: текст, голосовые, фото и скриншоты, ссылки,
пересланные посты. ИИ ([chutes.ai](https://chutes.ai)) раскладывает это по записям: задачи, события, идеи,
заметки, покупки, ссылки, мемы, цитаты. Из задач и событий бот делает напоминания, а ещё отвечает на вопросы
по сохранённому («что у меня завтра?»).

- Работает только с владельцем (`OWNER_ID`), остальных игнорирует.
- Long polling: входящие порты не нужны, достаточно Docker на ПК или Raspberry Pi.
- Есть [Mini App](#mini-app-необязательно) «📱 Свалка» внутри Telegram (по желанию, через бесплатный Tailscale Funnel).
- Всё хранится в вашем PostgreSQL. Сами файлы бот не копирует, хранит только Telegram `file_id`.
- Расход на ИИ: примерно $0.3–1 в месяц при 30 сообщениях в день. Есть месячный лимит, по умолчанию $5.

Подробности: [требования](docs/requirements.md) и [архитектура](docs/architecture.md).

## Быстрый старт

Нужны [Docker Desktop](https://www.docker.com/products/docker-desktop/) (Windows/macOS) или Docker Engine
с плагином Compose (Linux/Raspberry Pi).

1. **Создайте бота.** В Telegram откройте [@BotFather](https://t.me/BotFather), отправьте `/newbot` и
   сохраните токен вида `123456789:AA…`.
2. **Получите ключ chutes.ai.** Зарегистрируйтесь на [chutes.ai](https://chutes.ai), пополните баланс
   (оплата по факту, $5 хватит надолго) и создайте API-ключ `cpk_…`.
3. **Заполните `.env`:**
   ```bash
   cp .env.example .env        # PowerShell: Copy-Item .env.example .env
   ```
   Впишите `BOT_TOKEN`, `CHUTES_API_KEY`, придумайте `POSTGRES_PASSWORD` (только буквы и цифры) и
   повторите его в `DATABASE_URL`. `OWNER_ID` пока оставьте `0`.
4. **Запустите:**
   ```bash
   docker compose up -d --build
   ```
   Поднимутся три контейнера: `db` (PostgreSQL 18), `migrate` (создаёт таблицы и завершается) и `bot`.
5. **Узнайте свой Telegram ID.** Отправьте боту `/start`, он ответит вашим ID. Впишите его в `.env`
   (`OWNER_ID=123456789`) и пересоздайте контейнер бота:
   ```bash
   docker compose up -d
   ```
   Команда `docker compose restart` новый `.env` **не подхватывает**, нужен именно `up -d`.

Готово: отправьте `/help` или просто напишите «завтра в 10 позвонить в банк».

## Как пользоваться

### Отправляйте что угодно

| Что отправили | Что сделает бот |
|---|---|
| Текст | Разберёт на одну или несколько записей («купить молоко и в пятницу к врачу в 15:00» → покупка + событие) |
| Голосовое или аудиофайл (в том числе пересланный), до 5 минут | Распознает речь (Whisper на chutes или [локальный Whisper](#локальный-whisper-необязательно)), дальше как с текстом |
| Фото / картинка файлом | Прочитает текст на картинке (OCR) и определит категорию |
| Ссылка | Сохранит её и сам подтянет заголовок страницы |
| Пересланный пост | Сохранит вместе с источником (канал или автор, ссылка) |
| Видео, кружочек, стикер, документ, геолокация | Запись «Другое»; подпись, если она есть, разберёт ИИ. Кружочки не распознаются |

Сообщение, которое начинается с **`?`**, всегда считается вопросом: `? что я сохранял про отпуск`.
Без `?` бот сам решает, сохранить это или ответить.

**Категории:** Задача, Событие/напоминание, Идея, Мысль/заметка, Покупка, Ссылка/сохранёнка, Мем, Цитата,
Другое. Теги ИИ ставит сам. Категорию, теги и всё остальное можно поправить вручную.

### Реакции бота на ваше сообщение

| Реакция | Значение |
|---|---|
| 👀 | Получено, обрабатываю |
| 👌 | Сохранено |
| ✍ | Отложено: ИИ временно недоступен или исчерпан бюджет. Сообщение сохранено и обработается само |
| 🤔 | Нужен ваш ответ: бот задал уточняющий вопрос с кнопками |
| 😢 | Не получилось разобрать сообщение или применить правку. Сообщение сохранено (текст — заметкой, без напоминаний), подробности в логах |

На заметки, идеи, мемы и ссылки бот отвечает только реакцией 👌. На задачи и события он присылает
карточку с временем, напоминанием и кнопками.

### Правка записей

- **Ответьте (reply) на карточку бота** текстом: «перенеси на 18:00», «это идея, а не задача»,
  «напомни за час», «удали». ИИ применит правку.
- Заметки и идеи карточки не получают (только 👌): чтобы поправить такую запись, **ответьте на своё сообщение**,
  из которого она сохранена («это задача, напомни вечером»). Если из сообщения вышло несколько записей, бот
  спросит, какую менять.
- На уточняющий вопрос 🤔 и на список «Какую запись изменить?» можно ответить кнопкой или ответом (reply)
  текстом: «вечера», «2».
- Правка без ответа на карточку («перенеси встречу с Олегом на 16») применяется сразу, только если запись
  нашлась однозначно (все слова) и это не «удали» / «сделано» / «без напоминания» / «стоп повтор»: в остальных
  случаях бот покажет список и спросит. Если ничего не нашлось, сообщение сохранится обычной заметкой.
- **Кнопка «✏️ Изменить»** в карточке открывает меню: время, категория, теги, название, «напомнить за…».
  После «🕒 Время», «✏️ Название» или «#️⃣ Теги» ответом считается только набранный текст (для времени — и
  голосовое), отправленный в течение 5 минут или ответом (reply) на запрос бота. Пересланный пост, ответ на
  другую карточку, вопрос с «?» или сообщение позже — это уже обычная запись, а ввод отменяется.
- Если из задачи без времени сделать идею или заметку, её напоминание в 19:00 отменяется.
- Кнопки «🔕 Без напоминания» и «🗑 Удалить» (с возможностью вернуть). «✅ Готово» — в самом напоминании
  и в меню «✏️ Изменить» (в карточке создания её нет, чтобы не мешала).
- Если отредактировать своё исходное сообщение в Telegram, запись **не** изменится.

### Шаги (чек-лист) и похожие записи

- **Разбить задачу на шаги** можно тремя способами: сразу в сообщении («переезд в субботу, распиши по шагам»),
  кнопкой «🪄 Разбить на шаги» в карточке открытой задачи или ответом на карточку «разбей на шаги» (можно с
  пожеланием: «на 3 шага, начни с документов»). ИИ предложит 2–8 шагов; кнопка и ответ — это отдельный
  недорогой вызов ИИ (в `/usage` — «разбивка на шаги»). Повторяющиеся задачи и сами шаги не разбиваются. Если
  месячный бюджет на ИИ исчерпан, кнопка ничего не ставит в очередь и сразу говорит, до какого числа.
- Карточка задачи показывает чек-лист «☐ 1. Упаковать вещи / ☑ 2. Заказать машину» и кнопку ☐/☑ на каждый
  шаг. Когда отмечены все, задача закрывается сама (её напоминания отменяются), а отдельным сообщением приходит
  «🎉 Все шаги выполнены — «Переезд» закрыт». То же — если удалить последний неотмеченный шаг. Снятая отметка,
  новое время у отмеченного шага или возвращённый из удалённых неотмеченный шаг снова открывают задачу.
- «Готово» у самой задачи отмечает и все её шаги; «↩️ Не сделано» сразу после снимает именно эти отметки (шаги,
  отмеченные раньше, остаются отмеченными, напоминания шагов со временем возвращаются). «↩️ Не сделано» у задачи,
  которую закрыл последний отмеченный шаг, снимает отметку с этого шага.
- У задачи с шагами и у самого шага не бывает повтора: отметки шагов были бы общими для всех раз. Ответ
  «каждую субботу» на такую карточку повтор не включит (дата, если она названа, сменится) — карточка предупредит.
- Шаг без времени не напоминает (иначе каждый шаг пинговал бы в 19:00) и виден только в карточке задачи. Шаг со
  временем («заказать машину в четверг в 15») напоминает как обычная задача и стоит в `/tasks`, `/today` и
  дайджестах с пометкой «(из «Переезд»)»; в `/tasks` у задачи виден прогресс «2/5».
- Удаление задачи удаляет её шаги, «↩️ Вернуть» возвращает их. «↩️ Вернуть» у шага удалённой задачи (например,
  в старом напоминании шага) возвращает всю задачу.
- **«🔗 похоже на …»**: перед разбором бот находит до 5 старых записей (за год) с теми же словами и показывает их
  ИИ; если какие-то действительно про то же самое, в карточке появляется строка «🔗 похоже на: «Купить наушники
  Sony» (12 сен)» и кнопка «🔗 Похожее», которая присылает карточки этих записей. Это только подсказка: записи
  не объединяются («вдруг нужна ещё одна пара наушников»).

### Команды

| Команда | Что делает |
|---|---|
| `/today` | План на сегодня и просроченное |
| `/tasks` | Открытые задачи, события и покупки (без «когда-нибудь»); у задачи с чек-листом — прогресс «2/5», шаги со временем — отдельными строками |
| `/someday` | Записи «когда-нибудь»: без срока и без напоминаний |
| `/recent` | Последние сохранённые записи |
| `/search <текст>` | Поиск по записям (полнотекстовый, RU/EN). Без текста (из меню команд) бот попросит ответить ему тем, что найти |
| `/ask <вопрос>` | Вопрос по базе обычным языком: «что у меня на выходных?» Без текста — так же, ответом на сообщение бота |
| `/recurring` | Повторяющиеся задачи (здесь же их можно остановить) |
| `/settings` | Настройки: часовой пояс, время слов «утро/вечер…», напоминания, тихие часы, дайджесты, бюджет, голос (язык и распознавание: chutes или локальный Whisper) |
| `/usage` | Расходы на ИИ за текущий месяц |
| `/help` | Справка |
| `/cancel` | Выйти из ввода (правка записи, настройки) |
| `/start` | Приветствие (пока `OWNER_ID=0`, отвечает вашим Telegram ID) |

## Время, напоминания, дайджесты

Часовой пояс по умолчанию `Europe/Warsaw`, переход на летнее и зимнее время учитывается. Меняется в `/settings`.

### Слова времени (настраиваются в `/settings`)

| Слова | Время |
|---|---|
| утром | 09:00 |
| в обед | 13:00 |
| днём | 15:00 |
| вечером | 19:00 |
| после работы | 18:30 |
| ночью | 22:00 |
| на выходных | суббота 11:00 |
| дата без времени («завтра», «в пятницу») | 10:00 |
| задача без даты и времени | 19:00 |

- Если время сегодня уже прошло, бот берёт завтрашнее: «в обед», сказанное в 15:00, — это завтра в 13:00.
- Сегодняшняя дата без времени остаётся сегодня, даже если 10:00 уже прошло: «сегодня купить молоко» днём —
  напоминание в 19:00, вечером — через час (не позже 23:59).
- Задача без времени, присланная после 19:00, получит напоминание завтра в 19:00. Это касается только
  задач, событий и покупок. Идеи и заметки без времени напоминаний не получают.
- После полуночи до 04:00 «завтра» означает уже наступивший день: «завтра утром», сказанное в 01:30, — это
  09:00 этого же дня.
- «Через 20 минут» — ровно через 20 минут. «В пятницу», «в следующий вторник», «5-го», «15.10» тоже понимает.
- Если дата в прошлом или время выглядит подозрительно («в 3» — ночи или дня?), бот сохранит запись и
  попросит подтвердить в карточке.

### Размытые сроки

| Фраза | Как понимает бот | Напоминания |
|---|---|---|
| «на этой неделе», «на следующей неделе» | неделя пн–вс | в последний рабочий день срока в 19:00 (если он уже прошёл — в последний день срока в 19:00) и утром первого дня (10:00), если срок ещё не начался |
| «в этом месяце», «в следующем месяце», «в октябре» | календарный месяц; прошедший месяц — в следующем году | так же |
| «весной», «летом», «осенью», «зимой» | ближайший ещё не закончившийся сезон (зима — дек–фев) | так же |
| «до пятницы», «к 15-му», «до конца недели / месяца», «к лету», «до октября» | срок (дедлайн); «до конца недели» — последний рабочий день; «к лету», «до октября» — первый день срока (1 июня, 1 октября) | накануне в 19:00 и в сам день в 10:00; со временем («до пятницы 15:00») — накануне в 19:00 и за 5 минут |
| «на днях» | через 2 дня | одно напоминание через 2 дня в 19:00 |
| «когда-нибудь», «потом как-нибудь» | без срока | нет; запись видна в `/someday`, а не в `/tasks` |

- Пока срок идёт, такие дела каждое утро стоят в дайджесте отдельным разделом («🗓 На этой неделе», «🗓 В этом
  месяце», «🗓 Этой осенью») и в `/today`; после окончания срока невыполненное попадает в «Просрочено».
- Карточка показывает срок словами: «🗓 на этой неделе (до вс 11 окт) · напомню пт в 19:00»,
  «⏳ до пт 9 окт · напомню чт в 19:00 и пт в 10:00», «🌙 когда-нибудь».
- Срок можно поменять ответом на карточку: «перенеси на следующую неделю», «давай когда-нибудь», «на завтра».
  Конкретная дата или «📅 Перенести на завтра» в вечернем итоге превращают размытый срок в обычную дату.
- «Когда-нибудь» — это без даты совсем: повтор останавливается (и не оживает после «🗑 → ↩️ Вернуть»), а
  «↩️ Не сделано» на старом напоминании такой записи только снимает отметку — дату и напоминания не возвращает.
  «Каждую пятницу» в ответ на такую запись начинает повтор с ближайшей пятницы; «каждый день» у записи «на этой
  неделе» — с сегодняшнего дня (у «на следующей неделе» — с её понедельника).
- Напоминания размытых сроков и «накануне» у дедлайнов бот назначает сам: в тихие часы они не приходят, а
  сдвигаются на их конец. Напоминание к точному времени дедлайна («до пятницы 15:00») приходит как обычно.

### Напоминания

- Для событий с точным временем бот напоминает **за 5 минут** (значение меняется в `/settings`). В сообщении
  можно задать своё: «напомни за 30 минут», «за день» — в том числе для «через 2 часа» и «напомни в 15:00».
- Задачам без точного времени (только дата или вообще ничего) бот напоминает ровно в назначенное время:
  10:00 для даты, 19:00 для задачи без даты.
- Напоминание появляется сразу, в карточке есть кнопки «изменить» и «отменить».
- В самом напоминании есть кнопки ✅ Готово, ⏰ 15 мин, ⏰ 1 час и 📅 Завтра. Отложенное напоминание заменяет
  только те, что пришли бы раньше него: «за 30 минут» после напоминания «за день» останется.
- Если не нажать «Готово», бот повторно **не** напоминает: задача просто попадёт в вечерний итог.
- Если в момент напоминания нет интернета или Telegram недоступен, бот повторяет отправку каждые
  `SCHEDULER_INTERVAL_S` (30 с), пока не получится. Опоздавшее больше чем на 6 часов напоминание уже не приходит,
  а попадает в вечерний итог.

### Тихие часы (по умолчанию 23:00–08:00)

Напоминание на время, которое вы назвали сами («в 23:30»), придёт как обычно. Всё, что бот назначил сам
(дайджесты, напоминания задач без времени), он сдвигает на конец тихих часов — и не присылает в тихие часы,
даже если опоздал (компьютер спал). Тихие часы можно выключить или поменять в `/settings`.
Ответы на сообщения, разобранные ночью (например, отложенные из-за бюджета или недоступности ИИ), приходят
в тихие часы без звука.

### Дайджесты

- **Утренний, 09:00:** задачи на сегодня, просроченные и дела с размытым сроком, который сейчас идёт
  («🗓 На этой неделе»).
- **Вечерний, 21:00:** что сделано и что нет, плюс кнопка «📅 Перенести невыполненное на завтра». Она переносит
  только то, что уже наступило; дела, которые ещё впереди этим вечером, показаны отдельно и остаются на месте.
- Пустой дайджест бот не присылает. Время и включение настраиваются в `/settings`.

### Повторяющиеся задачи

«Каждый понедельник в 9 выносить мусор», «каждые 2 недели», «5-го числа каждого месяца»…
Кнопка «Готово» закрывает текущее повторение, следующее бот создаёт сам. Остановить повтор можно кнопкой
«⏹ Стоп повтор» в карточке или через `/recurring`.

## Бюджет и стоимость

- Основная модель: `google/gemma-4-31B-turbo-TEE`, около $0.12 за 1M входных и $0.37 за 1M выходных
  токенов. Одно сообщение — это ~2–3 тыс. токенов на входе и несколько сотен на выходе, то есть около $0.0004.
- Голосовое до 10 с стоит примерно $0.0005–0.001. [Локальный Whisper](#локальный-whisper-необязательно) бесплатен.
  Аудио длиннее 5 минут (`STT_MAX_DURATION_S`) не распознаётся ни там, ни там: сохраняется по подписи или как
  «Аудио: файл».
- Итого при 30 сообщениях в день: **примерно $0.3–1 в месяц**.
- Лимит по умолчанию **$5/мес** (`/settings`). При 80% бот предупредит. При 100% ИИ выключается до конца
  месяца: сообщения сохраняются (реакция ✍) и обрабатываются 1-го числа после тихих часов (по умолчанию в 08:00).
  Бюджет проверяется только перед платными вызовами: в режиме распознавания «Локальный» локальный Whisper
  распознаёт голосовое и при исчерпанном бюджете (текст сохранится, а разбор подождёт). В режиме «Авто» первым идёт
  платный chutes, поэтому голосовое ждёт целиком — и распознавание, и разбор. Текущие траты показывает `/usage`.
- Если chutes недоступен, сообщение ждёт в очереди и обрабатывается позже: повторы с паузой до 6 ч,
  плюс запасные модели.

## Приватность

Всё, что вы отправляете боту (текст, голосовые, картинки, пересланные посты), **уходит в chutes.ai** на
распознавание и разбор. Модели с суффиксом `-TEE` работают в доверенной среде исполнения (TEE), но всё
равно исходите из того, что данные покидают ваш компьютер. Не отправляйте боту пароли и данные карт.
Заголовки ссылок бот загружает сам, напрямую с этих сайтов. База данных хранится только у вас.
С [локальным Whisper](#локальный-whisper-необязательно) в режиме «Локальный» сам звук голосовых обычно остаётся на
вашем компьютере, но распознанный текст всё равно уходит в chutes.ai на разбор. «Обычно» — потому что при отказе
локального сервиса звук уходит в chutes: голосовое длиннее `WHISPER_MAX_AUDIO_S` (по умолчанию 120 с; бот
распознаёт до 5 минут), контейнер `whisper` остановлен, перезапускается или ещё качает модель, распознавание не
уложилось в `LOCAL_STT_TIMEOUT_S`. Чтобы голосовые до 5 минут оставались локальными, поставьте
`WHISPER_MAX_AUDIO_S=300` и `LOCAL_STT_TIMEOUT_S=300` (на медленном процессоре — больше). Режима «только локально»
без запасного chutes нет.
С [Mini App](#mini-app-необязательно) веб-сервер бота доступен из интернета через Tailscale Funnel (TLS
заканчивается на вашем компьютере, Tailscale видит только зашифрованный трафик). Каждый запрос к данным проверяется
подписью Telegram и принимается только от `OWNER_ID`; без этой подписи виден лишь статический фронтенд.

## Эксплуатация

```bash
docker compose ps                    # статус; у bot должно быть (healthy)
docker compose logs -f bot           # логи бота (Ctrl+C — выйти)
docker compose logs migrate          # если бот не стартует — сначала сюда
docker compose up -d                 # применить изменения .env (пересоздаёт контейнеры)
docker compose restart bot           # просто перезапустить
docker compose up -d --build         # обновление после изменения кода; миграции применятся сами
docker compose stop                  # остановить всё
docker compose down                  # удалить контейнеры; данные в томе pgdata сохраняются
```

Команда `docker compose down -v` **удаляет базу со всеми записями**.

Необязательные контейнеры `whisper` и `tailscale` эти команды затрагивают, только если их профили включены. Проще
всего перечислить профили в `.env`: `COMPOSE_PROFILES=whisper` (или `whisper,miniapp`) — Compose читает эту
переменную сам, и все команды выше работают со всем стеком. Без неё нужно каждый раз добавлять `--profile whisper`
/ `--profile miniapp`: иначе `stop` оставит `whisper` работать, `down` не удалит его и сеть («Resource is still in
use»), а `up -d --build` не пересоберёт и не пересоздаст его после изменения `WHISPER_*` в `.env`.

Если фоновая задача упала или зависла (планировщик молчит дольше 15 минут, очередь — дольше 30), бот
пишет об этом в лог (`made no progress`) и завершается, а `restart: unless-stopped` поднимает его заново.
Healthcheck бота следит за файлом-«пульсом» планировщика: если тот не обновлялся дольше четырёх интервалов
`SCHEDULER_INTERVAL_S` (минимум 120 с), контейнер помечается `unhealthy`. Это только индикатор: сам Docker такие
контейнеры не перезапускает.

### Локальный Whisper (необязательно)

Бесплатное распознавание голосовых прямо на вашем компьютере: отдельный контейнер `whisper`
([faster-whisper](https://github.com/SYSTRAN/faster-whisper) на процессоре, без видеокарты). Он выручает, когда
Whisper на chutes недоступен (это community-chute одного автора), и экономит бюджет. Подробности о сервисе —
в [whisper/README.md](whisper/README.md).

**Как включить:**

1. В `.env` впишите `LOCAL_STT_URL=http://whisper:9000` (базовый адрес сервиса, без `/transcribe`; остальные
   `WHISPER_*` можно не трогать, см. `.env.example`) и `COMPOSE_PROFILES=whisper` (с Mini App —
   `COMPOSE_PROFILES=whisper,miniapp`): тогда обычные команды из раздела «Эксплуатация» управляют и контейнером
   `whisper`.
2. Запустите стек как обычно (без профиля контейнер `whisper` не создаётся, а бот работает только с chutes):
   ```bash
   docker compose up -d --build        # без COMPOSE_PROFILES в .env: docker compose --profile whisper up -d --build
   ```
3. Необязательно, но удобно: заранее скачайте модель, чтобы первое голосовое не ждало загрузки:
   ```bash
   docker compose --profile whisper run --rm whisper python app.py --download
   ```
4. В боте: `/settings` → «🎙 Голос» → режим распознавания:
   - **Авто** (по умолчанию) — chutes, а если он недоступен или отказал — локальный;
   - **Локальный** — сначала локальный, при сбое — chutes;
   - **Только chutes** — локальный не используется.

   Пока `LOCAL_STT_URL` пуст, все режимы работают как «Только chutes» (в меню у «Локальный» пометка «не настроен»).
   Выключить: очистите `LOCAL_STT_URL`, уберите `whisper` из `COMPOSE_PROFILES`, выполните `docker compose up -d` и
   `docker compose --profile whisper stop whisper`.

**Первый запуск.** Модель скачивается с Hugging Face один раз — при первом голосовом (или командой из шага 3) — и
хранится в томе `whisper-models`; потом сервису интернет не нужен. Размеры: `tiny` ~75 МБ, `base` ~145 МБ,
`small` (по умолчанию) ~480 МБ, `medium` ~1,5 ГБ. При 50 Мбит/с `small` качается 1–2 минуты, при 10 Мбит/с — около
7 минут. Если загрузка не уложилась в `LOCAL_STT_TIMEOUT_S` (120 с), это голосовое распознает chutes (или бот
повторит попытку позже), а загрузка продолжится. Модель грузится в память при первом запросе (несколько секунд) и
остаётся там.

**Железо.** Сервис работает в Docker Desktop на Windows-ПК (WSL 2), на Linux и на Raspberry Pi (arm64).

| | Память | Заметки |
|---|---|---|
| Бот и Postgres | ~300 МБ | |
| Whisper `small` (int8) | ~1 ГБ во время работы | по умолчанию; лимит контейнера `WHISPER_MEM_LIMIT=2g` |
| Whisper `base` / `tiny` | ~0,3–0,5 ГБ | быстрее, но заметно хуже на русском |
| Whisper `medium` | ~2,5 ГБ | точнее, в 2–3 раза медленнее `small`; поставьте `WHISPER_MEM_LIMIT=4g` |

- **Windows-ПК:** хватит любого 4-ядерного процессора последних лет; `small` распознаёт 10-секундное голосовое за
  1–3 с (на старом 2-ядерном — до 10 с). Docker Desktop с WSL 2 по умолчанию отдаёт контейнерам половину
  оперативной памяти и все ядра; если памяти мало, лимит задаётся в `%UserProfile%\.wslconfig` (`[wsl2]`,
  `memory=4GB`). Во время распознавания процессор загружен полностью, но лишь на эти секунды; `WHISPER_THREADS`
  ограничивает число ядер.
- **Raspberry Pi 5:** 8 ГБ — комфортно, 4 ГБ — достаточно. **Pi 4:** используйте `WHISPER_MODEL=base` (`small` на
  нём медленный).
- Аудио длиннее `WHISPER_MAX_AUDIO_S` (120 с) локальный сервис не берёт — такое голосовое распознает chutes.
  Длину сервис проверяет по ходу декодирования (не по заголовку файла), поэтому файл «на несколько часов» не
  забивает память. Чтобы локально распознавались все голосовые до 5 минут, поставьте `WHISPER_MAX_AUDIO_S=300` и
  `LOCAL_STT_TIMEOUT_S=300`; на медленном процессоре держите `LOCAL_STT_TIMEOUT_S` с запасом выше
  `WHISPER_MAX_AUDIO_S` (на старом 2-ядерном распознавание идёт примерно в реальном времени). Если бот не дождался
  ответа, сервис бросает эту работу после текущего фрагмента и сразу берётся за следующее голосовое.
- Сервис не публикуется на хост: к нему обращается только бот по сети compose. Если бот запущен без Docker
  (`uv run python -m dumpbot`), опубликуйте порт (`ports: ["127.0.0.1:9000:9000"]` в `compose.override.yaml`) и
  укажите `LOCAL_STT_URL=http://127.0.0.1:9000`.
- Каждый вызов попадает в `/usage` (раздел «голосовые») с ценой $0: модель в учёте — `local:small`.

### Mini App (необязательно)

Приложение «📱 Свалка» внутри Telegram: сегодня и неделя, лента с поиском, фильтрами и превью картинок, задачи,
«когда-нибудь» и повторы, карточка записи со всеми правками (название, подробности, категория, теги, время текстом
через ИИ или пикером, «напомнить за», отложить, готово, удалить/вернуть, чек-лист, «🪄 разбить», похожие),
«закинуть в свалку», вопросы к базе, настройки и расходы. Открывается кнопкой меню бота (слева от поля ввода).
API приложения описан в [docs/features/miniapp-api.md](docs/features/miniapp-api.md).

Внутри приложения: внизу вкладки «Сегодня» (план, просроченное, «на этой неделе», «📅 Перенести невыполненное на
завтра», переключатель «7 дней»), «Лента», «➕ Добавить», «Задачи» (открытые / когда-нибудь / повторы) и «Ещё»
(вопросы, корзина, настройки, расходы). Тап по записи открывает карточку; кнопка «Назад» в шапке Telegram
возвращает обратно, синяя кнопка внизу сохраняет правки. ☐ в списке отмечает именно эту строку — вечером утренний
раз ежедневной задачи, а не завтрашний. Несохранённый текст («Добавить», карточка, настройки) не пропадает при
переходе на другую вкладку и когда сессия устарела (через сутки): он вернётся, когда приложение откроют снова.
Тема (светлая / тёмная) берётся из Telegram. Фронтенд (React + TypeScript + Vite, папка `webapp/`) собирается при
`docker compose build` внутри образа бота — Node на компьютере не нужен.

Telegram открывает Mini App только по HTTPS-адресу из интернета. Своего домена не нужно: адрес
`https://dump.<ваш-tailnet>.ts.net` бесплатно даёт **Tailscale Funnel** — контейнер `tailscale` (профиль compose
`miniapp`) получает сертификат и проксирует HTTPS на веб-сервер бота (`http://bot:8080`). Наружу видно только его:
Postgres и остальное остаются внутри сети Docker, на хосте ничего не открывается, роутер настраивать не нужно.

**Один раз руками (10 минут):**

1. **Регистрация.** Откройте [login.tailscale.com/start](https://login.tailscale.com/start) и войдите через Google,
   GitHub или Microsoft — бесплатный план Personal подходит. Приложение Tailscale на ПК ставить не нужно.
2. **DNS и сертификаты.** В админке откройте [DNS](https://login.tailscale.com/admin/dns): **MagicDNS** должен быть
   включён (кнопка «Enable MagicDNS», если он выключен), а внизу страницы в разделе **HTTPS Certificates** нажмите
   «Enable HTTPS». Там же вверху написано имя вашего tailnet (**Tailnet DNS name**), например `tail1234.ts.net` —
   оно понадобится в шаге 5.
3. **Funnel разрешён.** Откройте [Access controls](https://login.tailscale.com/admin/acls/file) и проверьте, что в
   политике есть атрибут `funnel` (в новых tailnet он есть по умолчанию):
   ```json
   "nodeAttrs": [
     {"target": ["autogroup:member"], "attr": ["funnel"]}
   ]
   ```
   Если блока нет — добавьте его и нажмите «Save».
4. **Ключ.** [Settings → Keys](https://login.tailscale.com/admin/settings/keys) → «Generate auth key…»: Reusable и
   Ephemeral **не** включайте (машина должна остаться в tailnet после перезапуска), остальное по умолчанию →
   «Generate key». Скопируйте ключ `tskey-auth-…` — его показывают один раз.
5. **`.env`:**
   ```
   TS_AUTHKEY=tskey-auth-…
   WEBAPP_ENABLED=true
   WEBAPP_URL=https://dump.tail1234.ts.net
   ```
   (`tail1234.ts.net` — имя из шага 2.) Ключ нужен только для первого запуска: дальше контейнер помнит себя в томе
   `tailscale-state`.
6. **Запуск** — как обычно, но с профилем `miniapp` (без него контейнер `tailscale` не создаётся). Удобнее всего
   добавить в `.env` `COMPOSE_PROFILES=miniapp` (с локальным Whisper — `COMPOSE_PROFILES=whisper,miniapp`), тогда
   все команды из «Эксплуатации» касаются и его:
   ```bash
   docker compose up -d --build        # без COMPOSE_PROFILES: docker compose --profile miniapp up -d --build
   ```
7. **Срок ключа.** В админке на странице [Machines](https://login.tailscale.com/admin/machines) у машины `dump`
   откройте меню «…» → **Disable key expiry**. Иначе примерно через полгода машина выпадет из tailnet и приложение
   перестанет открываться. Проверьте там же имя машины: если `dump` уже было занято, Tailscale назовёт её `dump-1`, и
   в `WEBAPP_URL` нужно имя `dump-1` (потом `docker compose up -d`).
8. **Telegram.** Закройте и снова откройте чат с ботом: слева от поля ввода появится кнопка «📱 Свалка» (иногда
   нужно перезапустить Telegram). Кнопку бот ставит при каждом старте, если `WEBAPP_ENABLED=true` и `WEBAPP_URL`
   начинается с `https://`; иначе там меню команд.

**Как проверить:**

```bash
docker compose --profile miniapp ps                              # у tailscale — (healthy)
docker compose logs bot | grep "Mini App"                        # "Mini App web server listening on 0.0.0.0:8080"
docker compose --profile miniapp exec tailscale tailscale funnel status   # https://dump.….ts.net (Funnel on) → http://bot:8080
curl -i https://dump.tail1234.ts.net/api/me                      # 401 {"error":{"code":"unauthorized",…}} — так и должно быть
```

Ответ 401 значит, что вся цепочка работает, а API защищён: данные отдаются только запросам, подписанным Telegram для
вашего `OWNER_ID` (initData не старше 24 часов). Тот же адрес в обычном браузере покажет стартовую страницу без
данных. Первый HTTPS-запрос может идти до минуты (Tailscale выпускает сертификат), а новое имя в публичном DNS
появляется в течение 10 минут.

Если не работает: `docker compose --profile miniapp logs tailscale` (ключ просрочен или уже использован — создайте
новый, очистите том: `docker compose --profile miniapp rm -sf tailscale` и `docker volume rm dumpbot_tailscale-state`,
запустите снова); `funnel status` пустой — проверьте шаги 2–3. Приложение пишет «Сессия устарела» — закройте его и
откройте кнопкой заново.

**Выключить:** `WEBAPP_ENABLED=false` в `.env` (и уберите `miniapp` из `COMPOSE_PROFILES`), `docker compose up -d`
(кнопка меню снова станет списком команд) и `docker compose --profile miniapp stop tailscale`.

Записи, добавленные через приложение, проходят тот же разбор ИИ, что и сообщения боту, но карточки и реакции в чат
не приходят — результат показывает приложение. Правки из приложения в чате не дублируются; только закрытие задачи
последним шагом чек-листа, как и в боте, присылает «🎉 Все шаги выполнены».

### Windows-ПК

Docker Desktop — обычное приложение: оно запускается, только когда вы входите в Windows, и только если в его
настройках включено **Start Docker Desktop when you sign in** (Settings → General). Поэтому после перезагрузки или
отключения света бот вернётся лишь после входа в систему. Перезагрузки после обновлений Windows обычно закрывает
параметр «Использовать мои данные для входа, чтобы автоматически завершить настройку после обновления»
(Параметры → Учётные записи → Варианты входа). Пока ПК спит или выключен, напоминаний нет: опоздавшие больше чем на
6 часов бот уже не присылает, они попадут в вечерний итог. Сообщения, присланные за это время, бот разберёт после
запуска (Telegram хранит их до 24 часов). Для работы 24/7 нужен всегда включённый компьютер (ПК без сна, мини-ПК или Raspberry Pi — см. ниже).

### DBeaver

PostgreSQL слушает только `127.0.0.1`, снаружи к нему не подключиться.

| Поле | Значение |
|---|---|
| Host | `127.0.0.1` |
| Port | `5432` (или `DB_HOST_PORT` из `.env`) |
| Database | `dump` |
| Username | `dump` |
| Password | `POSTGRES_PASSWORD` из `.env` |

Если бот работает на Raspberry Pi, включите в DBeaver вкладку **SSH** (хост Pi, пользователь `pi`), а в Host
укажите `127.0.0.1`.

### Бэкап (пока вручную)

Автоматических бэкапов нет. Если пропадёт том `pgdata`, пропадёт всё. Делайте дамп хотя бы раз в неделю и
храните копию вне этого компьютера. Команды одинаково работают в bash и PowerShell:

```bash
mkdir ../dumpbot-backups            # один раз
docker compose exec db sh -c "pg_dump -U dump -d dump -Fc -f /tmp/dump.backup"
docker compose cp db:/tmp/dump.backup ../dumpbot-backups/dump-2026-10-06.backup
```

Восстановление (например, на новой машине):

```bash
docker compose up -d db
docker compose cp ../dumpbot-backups/dump-2026-10-06.backup db:/tmp/dump.backup
docker compose exec db sh -c "pg_restore -U dump -d dump --clean --if-exists --no-owner /tmp/dump.backup"
docker compose up -d --build
```

`sh -c "…"` здесь нужен для Git Bash на Windows: без него он подменяет путь `/tmp/…` на виндовый.

Бэкапы лучше держать вне папки проекта: в них все ваши записи, и в git им не место.

### Переезд на Raspberry Pi 4/5

1. **Pi:** Raspberry Pi 4 (от 4 ГБ) или 5 с **64-битной** Raspberry Pi OS Lite: `dpkg --print-architecture`
   должен показать `arm64` (`armhf` — 32-битная система, образ на ней не соберётся). `uname -m` для проверки не
   годится: он показывает ядро, а оно на Pi 64-битное и у 32-битной системы. Лучше загружаться с SSD, а не с
   SD-карты: база пишет на диск постоянно.
2. **Docker на Pi:** по [официальной инструкции](https://docs.docker.com/engine/install/debian/) или
   `curl -fsSL https://get.docker.com | sh`, затем `sudo usermod -aG docker $USER` и перелогиниться.
3. **На ПК:** сделайте бэкап (см. выше) и остановите бота: `docker compose stop bot`. С одним токеном может
   работать только один экземпляр, иначе будет 409 Conflict.
4. **Скопируйте на Pi** проект (без `.venv`), `.env` и бэкап, например через `git clone` или `scp -r`.
5. **На Pi:** восстановите базу (команды из раздела «Бэкап») и запустите `docker compose up -d --build`.
   Образ соберётся прямо на Pi под arm64 за несколько минут: компилировать ничего не нужно, все зависимости
   ставятся готовыми wheel-пакетами.

   Можно собрать образ и на ПК (через эмуляцию QEMU в Docker Desktop, это медленнее), а на Pi только
   загрузить:
   ```bash
   # на ПК
   docker buildx build --platform linux/arm64 -t dumpbot:arm64 --load .
   docker save dumpbot:arm64 -o dumpbot-arm64.tar
   # на Pi (после копирования файла)
   docker load -i dumpbot-arm64.tar
   docker tag dumpbot:arm64 dumpbot:local
   docker compose up -d --no-build
   ```
6. Проверьте `docker compose ps` и `/today` в Telegram. Только после этого удаляйте контейнеры на ПК
   (`docker compose down`, том с данными пусть пока останется).

Часовой пояс системы на Pi роли не играет: контейнеры работают в UTC, а бот берёт пояс из `/settings`.

## Разработка

Нужны Python 3.12 и [uv](https://docs.astral.sh/uv/).

```bash
uv sync                                   # зависимости, включая dev (pytest, ruff)
docker compose up -d db                   # только база (127.0.0.1:5432)
uv run alembic upgrade head               # миграции; URL берётся из DATABASE_URL в .env
docker compose stop bot                   # не запускайте два бота с одним токеном
uv run python -m dumpbot                  # бот локально
```

**Тесты.** Интеграционным тестам нужен отдельный одноразовый Postgres, без него они пропускаются. Схему
тесты создают сами и очищают её после каждого теста.

```bash
docker run -d --name dump-test-db -e POSTGRES_USER=dump -e POSTGRES_PASSWORD=dump \
  -e POSTGRES_DB=dump_test -p 127.0.0.1:55432:5432 postgres:18

TEST_DATABASE_URL=postgresql+asyncpg://dump:dump@127.0.0.1:55432/dump_test uv run pytest
# PowerShell:
# $env:TEST_DATABASE_URL = "postgresql+asyncpg://dump:dump@127.0.0.1:55432/dump_test"; uv run pytest

docker rm -f dump-test-db
```

`tests/e2e/` прогоняет всё приложение целиком (long polling, очередь, ИИ, планировщик, кнопки) против локальных
фейков Telegram и chutes.ai — в сеть ничего не уходит: `uv run pytest tests/e2e`.

**Стиль:** `uv run ruff check . --fix` и `uv run ruff format .`

**Фронтенд Mini App** (`webapp/`, нужен Node 22+). С мок-API в памяти — без бота, Telegram и сети:

```bash
cd webapp
npm ci
npm run dev        # http://127.0.0.1:5173 — мок-API (webapp/mock/), данные живут до перезапуска
npm run check      # tsc --noEmit + eslint + vitest + сборка
npm run build      # webapp/dist — то же, что попадает в образ (/app/webapp)
```

В обычном браузере кнопки «Назад» и «Сохранить» рисует само приложение (в Telegram это его кнопки). Мок понимает
слова: «?…» — вопрос, «уточни …» — уточняющий вопрос, «перенеси …» — выбор записи, «бюджет» — ждёт бюджета, «ошибка» —
сбой. Против настоящего бота: `VITE_API_PROXY=http://127.0.0.1:8080` и в `VITE_DEV_INIT_DATA` — свежая initData
владельца (иначе сервер ответит 401).

**Миграции.** После изменения `src/dumpbot/db/models.py`:

```bash
uv run alembic revision --autogenerate -m "add something"   # новый файл в migrations/versions/
uv run alembic upgrade head
uv run alembic check                                       # «No new upgrade operations detected»
```

Сгенерированную миграцию всегда просматривайте глазами. Изменения генерируемой колонки `items.search_tsv`
autogenerate не видит, их нужно писать вручную.

## Решение проблем

| Симптом | Причина и что делать |
|---|---|
| В логах `409 Conflict: terminated by other getUpdates request` | Два экземпляра бота с одним токеном (Docker и локальный запуск, ПК и Pi). Остановите лишний |
| Бот молчит | Проверьте `OWNER_ID` и `docker compose logs bot`. После правки `.env` нужен `docker compose up -d`, а не `restart` |
| Бот не стартует, `migrate` завершился с ошибкой | `docker compose logs migrate`. Бот ждёт успешной миграции |
| Голосовые не распознаются | Включите `STT_CONVERT_WAV=true` и выполните `docker compose up -d`. Если в логах `503 No instances available`, Whisper-chute на chutes временно не работает: сообщение ждёт в очереди (✍) и обработается позже. Чтобы не ждать, включите [локальный Whisper](#локальный-whisper-необязательно) |
| В логах бота `local STT unreachable` | Контейнер `whisper` не запущен (запускайте с `--profile whisper`) или `LOCAL_STT_URL` указан неверно. Голосовые пока распознаёт chutes |
| `local STT HTTP 503` | Локальный Whisper не смог загрузить модель (нет интернета при первом запуске, мало памяти). `docker compose logs whisper`; при нехватке памяти увеличьте `WHISPER_MEM_LIMIT` или возьмите модель поменьше |
| От chutes приходит `401` | Неверный `CHUTES_API_KEY` |
| От chutes приходит `402` | На chutes.ai закончился баланс, пополните |
| От chutes приходит `404` | Модель переименовали или убрали. Пока отвечает запасная модель, бот работает на ней и раз в день напоминает об этом. Выберите другую на chutes.ai и поменяйте `LLM_MODEL` / `*_FALLBACK_MODEL` в `.env` |
| Реакция ✍ и долго ничего | chutes недоступен или исчерпан бюджет (`/usage`). Очередь повторит сама |
| `port is already allocated` / 5432 занят | На хосте уже есть другой Postgres. Задайте `DB_HOST_PORT=5433` и поправьте порт в `DATABASE_URL` |
| `password authentication failed` после смены `POSTGRES_PASSWORD` | Пароль задаётся только при первом создании базы. Верните старый или смените его в самой базе: `docker compose exec db psql -U dump -d dump -c "ALTER USER dump PASSWORD 'новый'"` |
| `bot` в статусе `unhealthy` | Планировщик отстаёт. Посмотрите `docker compose logs bot`: зависший цикл бот перезапускает сам (`made no progress`). `TimeoutError` от базы обычно значит, что блокировку держит незакрытая транзакция, например в DBeaver: завершите её |
