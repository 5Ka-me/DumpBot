# Итерация 3: по итогам первых дней использования

Решение пользователя от 2026-10-09: делаем пункты 1–6 из разбора использования (31 сообщение за 3 дня: бот — напоминалка,
каждое 4-е сообщение — правка, задачи закрываются кнопкой в напоминании, ожидание карточки до 65 с, сон ноутбука).
Базовые требования — [../requirements.md](../requirements.md) (в т.ч. «только время уведомления»).

## 1. Быстрый переход на запасную модель
- **Пауза основной модели**: после 429 / таймаута / 5xx от `LLM_MODEL` бот 10 минут (`LLM_COOLDOWN_S=600`) сразу идёт в
  запасную (текст — `LLM_FALLBACK_MODEL`, картинки — `VISION_FALLBACK_MODEL`). Пауза в памяти процесса, по модели.
- **Параллельный запрос**: если основная модель не ответила за `LLM_HEDGE_AFTER_S=12` секунд, параллельно запускается
  запасная; берётся **первый валидный** (прошедший Pydantic) ответ, второй запрос отменяется. Оба вызова пишутся в `ai_usage`.
- Действует для разбора сообщений (`extract`); для `answer_query`/`split` — та же логика, если это просто сделать.
- Итог: худший случай карточки ~20 с вместо 65–73 с. Стоимость +$0.05–0.1/мес.

## 2. Кнопки «✅ N» в списках
- `/today`, `/tasks`, утренний и вечерний дайджест: строки открытых дел пронумерованы, под списком кнопки `✅ 1` `✅ 2` … (по 5 в ряд,
  не больше 20; для остального — подсказка про `/tasks` или Mini App).
- Нажатие закрывает дело (текущее повторение у повторяющихся; у родителя с чек-листом — родителя и его открытые шаги),
  сообщение со списком обновляется на месте: строка становится ✅ зачёркнутой, кнопка — `↩️ N` (отмена). Тост «✅ Закрыл «…»».
- ИИ не вызывается. Устаревшая кнопка (запись уже закрыта/удалена) — тост, без ошибок.
- Вечерний дайджест: кнопки для невыполненного + существующая «📅 Перенести невыполненное на завтра».

## 3. Правки описанием без лишнего шага
- «Закрой задачу про документацию», «перенеси визу на завтра», «удали X»: если **ровно одно** точное совпадение среди открытых записей —
  правка применяется сразу; ответ «✅ Закрыл «…»» / «🕒 Перенёс «…» на …» / «🗑 Удалил «…»» с кнопкой **«↩️ Отменить»**
  (возвращает прежние статус, время/повторение/напоминания, название, категорию, теги, период).
- Несколько или неточное совпадение — как сейчас список «Какую запись изменить?», но после выбора применяется **уже понятая**
  правка, без второго вызова ИИ.
- Промпт: «купил X», «сделал X», «готово: X» про существующую открытую задачу — это `edit` с `action=done` (одна строка правила).

## 4. Кнопка «🌙 Вечером» в напоминании
- Пока до вечернего слота (`slot_evening`, 19:00) больше часа: `[✅ Готово]` / `[⏰ 1 час] [🌙 Вечером] [📅 Завтра]`.
  Позже: `[✅ Готово]` / `[⏰ 15 мин] [⏰ 1 час] [📅 Завтра]`.
- «Вечером» переносит время записи на сегодня в `slot_evening` (как остальные «отложить»: запись переезжает).

## 5. Ничего не теряется после простоя
- Бот замечает простой (ноутбук спал, Docker стоял): разрыв между тиками планировщика по настенным часам ≥ 15 мин или старт
  процесса после такого разрыва (время последнего тика хранится в БД).
- Напоминание, опоздавшее больше чем на 30 мин и пришедшееся на тихие часы, ждёт конца тихих часов (`quiet_end`) и приходит
  беззвучно; в остальное время опоздавшее приходит как сейчас («опоздал на …»).
- Пропущенный вечерний итог не теряется: его «не сделано» попадает в следующий утренний дайджест отдельным разделом
  «Вчерашний итог (не успел прислать)».
- После простоя — одно **беззвучное** сообщение, только если что-то задело: «😴 Меня не было с 19:00 до 23:19 (компьютер
  спал?). Опоздало напоминаний: 1. Итог дня — в утреннем дайджесте.»

## 6. Расшифровка голосовых
- Любой ответ на голосовое показывает распознанный текст строкой «🎤 «…»» (в карточках).
- Если по голосовому создана только заметка/идея (обычно только 👌), бот присылает короткое сообщение
  «🎤 «…» → 💡 Идея «…»» с кнопками `[✏️ Изменить]` `[🗑 Не то — удалить]` — мусорные расшифровки сразу видны.

## Общее
- Тексты на русском, HTML экранируется, callback_data ≤ 64 байт, старые кнопки в уже отправленных сообщениях не ломаются.
- Mini App не трогаем, кроме мест, где общий код меняет поведение (например, отмена правки).
- Тесты: unit + БД + e2e на каждый пункт. README и `/help` — обновить.
