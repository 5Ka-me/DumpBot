## A. Размытые сроки (periods, deadlines, «на днях», «когда-нибудь»)

### Что говорит пользователь → что делает бот

| Фраза | Модель | Напоминания |
|---|---|---|
| «на этой неделе», «на следующей неделе» | период = календарная неделя (пн–вс) | (1) **утром первого дня периода**, если период ещё не начался: `bare_date_time` (10:00), auto; (2) **в последний рабочий день периода** (пн–пт) в `task_default_time` (19:00), auto. Если этот день уже прошёл или сегодня после 19:00 → последний день периода в 19:00; если и он прошёл → без (2). Напоминание (2) не отправляется, если задача уже сделана (это обычная логика: при done все pending отменяются). |
| «в этом месяце», «в следующем месяце», «в октябре» | период = календарный месяц. «в октябре», сказанное в ноябре → октябрь следующего года | те же правила (1) + (2) |
| «летом», «осенью», «зимой», «весной» | период = сезон (лето 1 июн–31 авг; зима 1 дек–28/29 фев) | те же правила (1) + (2) |
| «до пятницы», «к 15-му», «до конца недели» | **дедлайн** (`role=deadline`) | **оба**: накануне в `task_default_time` (19:00) и в день дедлайна в `bare_date_time` (10:00). Если у дедлайна есть точное время («до пятницы 15:00») — накануне в 19:00 и за `lead` до времени. Прошедшие моменты пропускаются. «до конца недели» = дедлайн в последний рабочий день. |
| «на днях» | срок через `soon_days` (2) дня | одно напоминание через 2 дня в 19:00, auto |
| «когда-нибудь», «потом как-нибудь», «someday» | без срока, флаг «когда-нибудь» | **нет**. Запись видна в `/someday`, не в `/tasks`. |

**Утренний дайджест** каждый день периода показывает раздел «🗓 На этой неделе» / «🗓 В этом месяце» /
«🗓 Этим летом» со всеми **открытыми** периодическими записями, чей период содержит сегодняшний день.

### Схема ИИ (`ai/schemas.py`)
`When` получает поле `period`:
```
period: str | None, pattern ^(this_week|next_week|this_month|next_month|\d{4}-\d{2}|spring|summer|autumn|winter|soon|someday)$
```
- `YYYY-MM` — конкретный месяц; ИИ пишет только месяц («в октябре» → `2026-10`), год выбирает код: прошедший месяц → следующий год.
- Сезон: ближайший ещё не закончившийся.
- `period` взаимоисключающее с `day`, `at`, `in_min`. Приоритет: `at` > `in_min` > `period` > `day`/`time`.
- «до …» → `day` + `role: "deadline"` (как сейчас). «до конца недели / месяца» → `period` + `role: "deadline"`: дедлайн = последний рабочий день периода (для месяца — последний рабочий день месяца).

Промпт (`ai/prompts.py`): грамматика `period` и примеры: «на этой неделе посмотреть Raspberry Pi», «в октябре поменять шины», «до пятницы сдать отчёт», «на днях позвонить Пете», «когда-нибудь выучить испанский». Поднять `PROMPT_VERSION` до `v2`.

### Домен (`domain/timeresolve.py`)
- `Precision` дополняется `"period"`; вместе с `"someday"` и `"soon"` это меняет `domain/kinds.py`, правка foundation здесь разрешена.
- `Resolution` (`dto.py`) получает поля:
  - `period_kind: str | None` (`week`, `month`, `season`, `soon`, `someday`);
  - `period_start: date | None`, `period_end: date | None` (локальные даты, включительно).
- `due_at`:
  - для периода — момент напоминания (2) или конец периода в 19:00, если (2) пропущено;
  - для `soon` — момент его напоминания;
  - для `someday` — `None`.
- Новая настройка в `Prefs`: `soon_days: int = 2`. Меню настроек менять не обязательно.
- Хелпер `period_bounds(period: str, now, prefs) -> tuple[date, date]` с тестами всех форм. Неделя начинается с понедельника. Учесть границы года и DST.

### Данные
Миграция Alembic, новая ревизия поверх текущей. Поля `items`:
- `period_kind String(16) NULL`
- `period_start Date NULL`
- `period_end Date NULL`
- `someday Boolean default false`

Индекс `(period_start, period_end)`.

### Сервисы и вид
- `items.create_items` / `apply_patch` сохраняют период. Правка `when.period` в ответе на карточку («перенеси на следующую неделю») пересчитывает напоминания.
- `query`:
  - `agenda()` получает поле `period_items: list[Row]` и подпись периода; `DigestData` / `Agenda` расширяются;
  - `open_tasks()` исключает `someday`;
  - новая функция `someday_items(session)`;
  - `run_query` с `range` учитывает пересечение периода записи с диапазоном.
- `views`:
  - строка времени в карточке: «🗓 на этой неделе (до вс 11 окт) · напомню пт в 19:00», «⏳ до пт 9 окт · напомню чт в 19:00 и пт в 10:00», «🌙 когда-нибудь»;
  - утренний дайджест с разделом периода;
  - команда `/someday` (роутер команд + `set_my_commands` + `/help` + README).

## B. Локальный Whisper (запасное или основное распознавание голоса)

Решения:
- Режим переключается в `/settings`:
  - `auto` — chutes, при его недоступности локальный; по умолчанию;
  - `local` — локальный, при сбое chutes;
  - `chutes` — только chutes.
- Модель скачивается один раз при первом запуске.
- Кружочки (`video_note`) **не** распознаём.
- Пересланные аудиофайлы (`audio`) распознаём как голосовые.

### Сервис `whisper/` (отдельный контейнер, compose profile `whisper`)
- Каталог `whisper/`:
  - `app.py` — aiohttp-приложение;
  - `Dockerfile`;
  - `requirements.txt` или `pyproject` — свой, отдельно от бота;
  - `README.md`.
- Использует `faster-whisper` (CTranslate2, CPU, `compute_type=int8`), есть колёса для amd64 и arm64.
- API:
  - `POST /transcribe` с JSON `{"audio_b64": str, "language": "ru"|"en"|null}` → `{"text": str, "language": str, "duration": float, "processing_ms": int}`;
  - `GET /health` → `{"status":"ok","model":...}`.
  - Принимает OGG/Opus, MP3, M4A, WAV: декодирует через PyAV из faster-whisper или через ffmpeg.
- Конфиг через env:
  - `WHISPER_MODEL` (по умолчанию `small`; варианты `tiny`, `base`, `small`, `medium`);
  - `WHISPER_THREADS` (по умолчанию — все ядра);
  - `WHISPER_BEAM_SIZE` (по умолчанию 1 — быстрее на Pi).
- Модель кэшируется в volume `whisper-models` и грузится лениво при первом запросе, затем держится в памяти. Ограничение длительности аудио — 120 с, иначе 413.
- Без внешней сети в рантайме, кроме первого скачивания модели с Hugging Face.
- В compose сервис `whisper`:
  - профиль `whisper`, то есть включается так: `docker compose --profile whisper up -d`;
  - не публикуется на хост, бот обращается к нему по `http://whisper:9000`;
  - healthcheck, `restart: unless-stopped`, лимит памяти (`mem_limit`) из env с разумным дефолтом.

### Бот
- `Settings`: `local_stt_url: str = ""` (пусто — локальный выключен), `local_stt_timeout_s: float = 120`.
- `ai/stt.py`:
  - `LocalWhisperSTT` (тот же протокол `SpeechToText`, `ai_usage` с `purpose="stt"`, `model="local:<model>"`, `cost=0`);
  - `RoutedSTT(primary_by_mode, ...)` выбирает порядок по `prefs.stt_mode` и при `AIUnavailable` пробует второй.
  - Если локальный не настроен (`local_stt_url` пуст), режимы `auto` и `local` работают как `chutes`. В меню режим `local` показывается с пометкой «(не настроен)».
- `Prefs.stt_mode: Literal["auto","local","chutes"] = "auto"`. Меню `/settings` → «🎙 Голос»: язык и режим.
- `processor`: `audio` (пересланный аудиофайл) обрабатывается как голос. Лимит длительности для chutes и для локального — 5 мин, длиннее → запись «Аудио» без распознавания. Бюджет проверяется только перед платными вызовами: локальный бесплатен.
- README:
  - как включить (`--profile whisper`, `LOCAL_STT_URL=http://whisper:9000`);
  - требования к железу (см. ниже);
  - время первого запуска.

### Требования к железу (для README)
- Бот и Postgres: около 300 МБ RAM.
- Whisper `small` int8: около 1 ГБ RAM при работе.
- Raspberry Pi 5 8 ГБ — комфортно; Pi 5 4 ГБ — достаточно.
- Pi 4: использовать `base` (`small` медленный).

## C. Связи со старыми записями и подзадачи

### C1. «🔗 Похоже на …» (без объединения, только подсказка)
- Перед разбором: кандидаты = до 5 неудалённых записей, похожих по словам на текст сообщения.
  - Похожесть — Postgres FTS с **OR** по лексемам сообщения, `to_tsvector('russian', …)` → `to_tsquery` с `|`, ранжирование `ts_rank`.
  - Исключить записи этого же сообщения; за последние 365 дней.
- Кандидаты уходят в промпт строкой `RELATED CANDIDATES` (id, kind, title, дата) — дешёво, без отдельного вызова. `ExtractedItem` получает `related: list[int]` (max 3): ИИ оставляет **только действительно** связанные id из кандидатов. Чужие id отбрасываются кодом.
- Таблица `item_links(item_id, related_id, kind='similar', created_at)`, PK `(item_id, related_id)`, обе ссылки FK на `items` с `ON DELETE CASCADE`.
- Карточка: строка «🔗 похоже на: «Купить наушники Sony» (12 сен)» (до 2 названий + «и ещё N») и кнопка «🔗 Похожее». Кнопка присылает карточки связанных записей отдельными сообщениями (до 3).
- Пользователь явно **не** хочет объединения дублей: «вдруг мне нужна ещё одна пара наушников».

### C2. Подзадачи (чек-лист)
- Модель: подзадача — это обычная запись с `parent_id` (FK `items.id`, `ON DELETE CASCADE`) и `position int`. Подзадача со временем получает свои occurrence и напоминания обычным механизмом.
  - Подзадачи **без времени не получают** дефолтное напоминание 19:00 — иначе каждый шаг будет пинговать.
- Создание:
  - а) кнопка «🪄 Разбить на шаги» в карточке актуальной задачи без подзадач → отдельный вызов ИИ (`purpose="split"`, схема `{steps: [{title, when?}]}`, 2–8 шагов, язык задачи);
  - б) словами — в самом сообщении («переезд, распиши по шагам») или ответом на карточку («разбей на шаги»). Разбор возвращает у записи `steps: list[{title, when?}]` (max 8) или `EditPatch.action = "split"`.
- Карточка родителя:
  - чек-лист «☐ 1. Упаковать вещи / ☑ 2. Заказать машину» с кнопкой-переключателем на каждый пункт (`SubCb`);
  - время пункта показывается рядом.
- Отметка пункта → occurrence или запись done; повторное нажатие снимает отметку.
- **Когда все пункты отмечены** → родитель автоматически done, его pending-напоминания отменяются, карточка обновляется. Отдельно приходит сообщение «🎉 Все шаги выполнены — «Переезд» закрыт» (пользователь просил уведомлять). Снятие отметки с пункта у закрытого родителя открывает родителя снова.
- Списки:
  - `/tasks` и дайджесты показывают подзадачи со временем как обычные задачи с суффиксом «(из «Переезд»)»;
  - подзадачи без времени в верхнеуровневых списках **не** показываются — они видны в карточке родителя;
  - в `/tasks` у родителя — прогресс «2/5».
- Миграция: `items.parent_id`, `items.position`, таблица `item_links`.

## D. Telegram Mini App (через бесплатный Tailscale Funnel)

Решения пользователя: в Mini App **все функции бота**; React + TypeScript + Vite; превью картинок — да;
открывается **только кнопкой меню бота** (без ссылок в карточках). Raspberry Pi не покупается — всё работает на Windows-ПК
в Docker (позже, возможно, мини-ПК). Домена нет → публичный HTTPS-адрес даёт **Tailscale Funnel** (`https://dump.<tailnet>.ts.net`).

### Публикация наружу
- Сервис `tailscale` в compose (профиль `miniapp`), образ `tailscale/tailscale` (multi-arch), userspace-режим (без `/dev/net/tun`,
  работает в Docker Desktop на Windows): `TS_AUTHKEY` из `.env`, `TS_HOSTNAME=dump`, `TS_STATE_DIR=/var/lib/tailscale` (volume),
  `TS_SERVE_CONFIG` → JSON (в репозитории, `tailscale/serve.json`): HTTPS 443 → `http://bot:8080`, `AllowFunnel` для `${TS_CERT_DOMAIN}:443`.
  Агент обязан сверить формат serve-конфига с актуальной документацией Tailscale (kb «Docker», «Funnel», «tailscale serve config»).
- Наружу проксируется **только** веб-сервер бота (порт 8080 внутри docker-сети); Postgres и остальное недоступны.
- Пользователь один раз делает руками (README, пошагово, со скриншотными подсказками словами): регистрация в Tailscale (бесплатно,
  вход через Google/GitHub/Microsoft) → в админке DNS включить MagicDNS и HTTPS Certificates → проверить, что Funnel разрешён в
  политике (nodeAttrs `funnel`) → создать auth key → вписать `TS_AUTHKEY` и `WEBAPP_URL` в `.env` → `docker compose --profile miniapp up -d`
  → в админке у машины `dump` отключить «key expiry».

### Бэкенд (внутри процесса бота)
- `Settings`: `webapp_enabled: bool = False`, `webapp_host: str = "0.0.0.0"`, `webapp_port: int = 8080`, `webapp_url: str = ""`
  (публичный URL для кнопки меню), `webapp_static_dir: str = "/app/webapp"`.
- aiohttp `web.Application` запускается в `Lifecycle` рядом с JobWorker/Scheduler (`web.AppRunner`/`TCPSite`), корректно
  останавливается. Отдаёт статику фронта (SPA fallback на `index.html`) и `/api/*`.
- **Аутентификация каждого `/api` запроса**: заголовок `Authorization: tma <initData>`; проверка подписи initData по алгоритму
  Telegram (HMAC-SHA256, ключ = HMAC("WebAppData", bot_token)), `auth_date` не старше 24 ч, `user.id == OWNER_ID`. Иначе 401/403.
  Ошибки и логи не содержат initData и токен.
- API (JSON, тонкий слой над существующими сервисами; бизнес-логику не дублировать):
  - `GET /api/feed?q=&kinds=&tags=&status=&from=&to=&cursor=` — лента записей (пагинация курсором), поиск = `query.search`/`run_query`.
  - `GET /api/today`, `GET /api/tasks`, `GET /api/someday`, `GET /api/recurring`, `GET /api/week` (повестка на 7 дней).
  - `GET /api/items/{id}` — полная карточка: поля, occurrence, напоминания, подзадачи, похожие, источник, превью-ссылки.
  - `PATCH /api/items/{id}` — title/details/kind/tags/lead/period/someday; `POST /api/items/{id}/when` `{text}` (как «🕒 Время»,
    через ИИ-джоб `edit_time`) и `{due_local: "YYYY-MM-DDTHH:MM"}` (прямая установка из пикера, без ИИ);
    `POST /api/items/{id}/done|undone|norem|delete|restore|stoprec|split|snooze {minutes|tomorrow}`;
    подзадачи: `POST /api/items/{id}/steps {title}`, `PATCH /api/steps/{id}`, `DELETE /api/steps/{id}`, `POST /api/steps/{id}/toggle`.
  - `POST /api/inbox {text}` — «закинуть в свалку» из приложения: тот же конвейер, что сообщение боту (RawMessage с
    `source=app`, синтетический message_id), без карточки в чате; `GET /api/inbox/{raw_id}` — статус обработки и созданные записи.
  - `POST /api/ask {question}` — вопрос к базе (тот же QuerySpec-путь) → `{answer, rows}`.
  - `GET/PATCH /api/settings` — все Prefs (валидация как в боте); `GET /api/usage`.
  - `GET /api/files/{item_id}/{n}` — превью картинки: бэкенд берёт `file_id` и отдаёт байты из Telegram (getFile), с кэшем в
    памяти (LRU, ≤ 50 МБ), только для картинок; авторизация как у API (фронт грузит через fetch → blob URL).
- Изменения из приложения будят планировщик так же, как кнопки в боте.
- Кнопка меню: при старте, если `webapp_enabled` и `webapp_url` заданы → `set_chat_menu_button(chat_id=OWNER_ID,
  MenuButtonWebApp(text="📱 Свалка", web_app=WebAppInfo(url=webapp_url)))`; иначе — стандартная кнопка команд.

### Фронтенд (`webapp/`)
- React 18+ + TypeScript + Vite; Telegram WebApp SDK (`telegram-web-app.js` или `@telegram-apps/sdk`); тема из `themeParams`
  (светлая/тёмная автоматически), `BackButton`/`MainButton` Telegram, haptic feedback.
- Экраны: **Сегодня** (повестка + просрочено + раздел периода), **Лента** (поиск, фильтры: категория, теги, статус, даты;
  превью картинок), **Задачи** (открытые, «когда-нибудь», повторяющиеся), **Карточка** (всё редактирование: название, детали,
  категория, теги, время текстом через ИИ или пикером, напомнить за…, без напоминания, отложить, готово/не сделано,
  удалить/вернуть, стоп повтор, подзадачи с чек-листом/добавлением/удалением/«🪄 разбить», похожие записи), **Добавить**
  (поле ввода → `/api/inbox`, показ результата), **Спросить** (вопрос → ответ), **Настройки** (все Prefs) и **Расходы**.
- Сборка в Docker: отдельная стадия `node:lts-slim` → `npm ci && npm run build` → `dist` копируется в образ бота
  (`/app/webapp`). Без внешних CDN, кроме скрипта Telegram WebApp. Локальная разработка: `npm run dev` с моком API.
- Тесты: бэкенд — unit + интеграционные (подпись initData, 401/403, каждый endpoint на БД); фронт — `vitest` для ключевой логики
  (api-клиент, форматирование) и `tsc --noEmit` + `npm run build` без ошибок.
